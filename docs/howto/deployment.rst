==============================
ビルドした静的サイトを公開する
==============================

MaatLog は Sphinx の拡張として動作し、最終的な成果物は静的な HTML サイトです。
本ページでは、 ``sphinx-build`` でビルドした静的サイトを公開する際に確認すべき事項を、
「ビルドした静的サイトを公開する」という 1 つの目的に絞って説明します

このページで扱わないもの:

* 特定のホスティングサービス(GitHub Pages、Netlify など)固有の設定手順
* 独自ドメイン、CDN、CI/CD によるデプロイ自動化
* ``html_baseurl`` ・Atom フィード・ビルダーそのものの詳細な設定仕様
  (それぞれ :doc:`../configuration` 、 :doc:`../builders` を参照してください)

ビルド成果物を確認する
----------------------

MaatLog がブログ機能一式(アーカイブ、Theme API の検証、Atom フィード、HTML メタ
データ注入)を保証するのは ``html`` ビルダーと ``dirhtml`` ビルダーです。
ビルダー
ごとの制約の詳細は :doc:`../builders` を参照してください

公開先へアップロードするディレクトリは、使用したビルダーによって異なります

* ``html`` ビルダー: ``-b`` では指定した出力先、 ``-M`` ではビルドディレクトリ直下の
  ``html`` (本リポジトリの手順では ``docs/_build/html``)
* ``dirhtml`` ビルダー: ``-b`` では指定した出力先、 ``-M`` ではビルドディレクトリ直下の
  ``dirhtml`` (本リポジトリの手順では ``docs/_build/dirhtml``)

公開作業に入る前に、実際に使用するビルダーとその出力ディレクトリを確認してください

公開前に html_baseurl を確認する
--------------------------------

``html_baseurl`` は、 ``html`` / ``dirhtml`` ビルダーで Atom フィードを有効にする
場合に **必須** の設定です。
設定項目そのものの仕様は :doc:`../configuration` を参照
してください

公開作業で特に注意が必要なのは、 ``html_baseurl`` の値が **実際に公開される URL**
と一致している必要がある点です。
次のようなケースでは値がずれやすいため、公開前に
必ず確認してください

* 公開先がサブパス配信の場合(例: ``https://example.com/docs/`` のように、ドメイン
  直下ではなくパスの下にサイトを配置する場合)
* 開発中に一時的な URL(プレビュー環境など)でビルドし、後から本番 URL へ切り替える
  場合

``html_baseurl`` が実際の公開 URL とずれていると、Atom フィードの ``link`` /
``id`` や HTML のフィードディスカバリに加え、canonical リンクやページ URL も、
公開後には存在しない URL を指してしまいます

Feed を公開する場合の注意点
---------------------------

``maatlog_generate_feeds`` は既定で有効(``True``)のため、設定を変更していない場合も
ビルド成功時にサイトフィードとタクソノミーフィードが書き出されます。
フィードの生成条件や
設定項目の詳細は
:doc:`../configuration` を参照してください

公開作業では、次の 2 点を確認してください

* フィードを公開する場合は、前節で説明したとおり ``html_baseurl`` が実際の公開
  URL と一致していること
* フィードの公開を意図していない場合は、 ``maatlog_generate_feeds = False`` を
  設定し、フィード生成とディスカバリリンクの両方を止めてから公開すること

公開ディレクトリをアップロードする
----------------------------------

ビルド成果物を公開先へ反映する手順は、特定のホスティングサービスに依存しない範囲
で次のとおりです

#. ``sphinx-build`` を実行し、警告が出ていないことを確認する
#. 「ビルド成果物を確認する」で確認した出力ディレクトリの中身を、公開先へまとめて
   反映する(``-M`` なら ``builddir/html`` や ``builddir/dirhtml``、 ``-b`` なら指定
   した出力先そのもの。
   本リポジトリでは ``docs/Makefile`` に対して
   ``make -C docs html`` を実行した場合 ``docs/_build/html`` となる)。
   なお ``-b`` の既定では出力先に ``.doctrees`` が置かれ、 ``-b`` / ``-M`` の
   どちらでも ``.buildinfo`` が出力ディレクトリ直下に残るため、これら Sphinx
   のビルドメタデータは公開対象から除外すること
#. ページとフィードが不揃いな状態を公開しないよう、ビルド成果物一式を一括で反映
   する(ページだけ新しくなり、フィードだけ古いままの状態を公開しない)
